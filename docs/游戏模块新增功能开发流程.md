# game 模块新增功能开发流程

本文基于项目现有实现总结，描述如何在 `game` 模块内新增一个完整业务功能。以下以“新增一个玩法模块”作为标准流程。

---

## 1. 先理解现有分层

在本项目里，一个新功能通常会拆成 5 层：

1. 协议层：`.proto`
2. 路由层：`MsgHandler`
3. 玩家模块层：`Module`
4. 跨服服务层：`GlobalService / RpcListenService`（如需要）
5. 配置表 / 系统层：`Tables / BaseSystem / ActivityLogic`（如需要）

判断新增功能属于哪种：

### 1）纯玩家本地模块

例如：

- 背包扩展
- 任务字段扩展
- 新的角色属性

通常只需要：

- 协议
- `MsgHandler`
- `Module`
- 数据存档

### 2）跨服共享模块

例如：

- 聊天
- 好友
- 邮件
- 玩家搜索

通常需要：

- game 服模块 / handler
- global 服 `@RpcService`
- game 服监听回调服务

### 3）系统型功能

例如：

- 活动
- 重置逻辑
- 排行
- 地图公共状态

通常需要：

- `GameSystem` 级系统
- 配置表
- 玩家模块
- 消息处理器

---

## 2. 标准开发步骤总览

新增一个功能，建议按下面顺序做：

1. 设计协议
2. 在 `packet.proto` 注册 TOPIC
3. 生成 proto Java 类
4. 新增玩家模块类
5. 在 `HumanObject.createModules()` 注册模块
6. 新增消息处理器 `MsgHandler`
7. 如有跨服逻辑，新增 global RPC 服务
8. 如有回推需求，新增 game 监听 RPC 服务
9. 如有配置，补充 Excel / Luban / Config 读取
10. 编译、启动、联调

---

## 3. 第一步：设计协议

## 3.1 新建 proto 文件

在目录下新增：

```text
gen/src/main/java/org/sunrise/game/genProto/proto/
```

例如：

```text
achievement.proto
```

## 3.2 协议文件命名规范

必须遵循：

- 文件名：小写下划线
- Java 类名：`XxxProto`
- TOPIC 名：`TOPIC_TYPE_XXX`

例如：

- 文件：`task.proto`
- Java：`TaskProto`
- TOPIC：`TOPIC_TYPE_TASK`

## 3.3 协议内容规范

每个模块通常包含：

- `FROM_CLIENT`
- `FROM_SERVER`
- `message MC2S_xxx`
- `message MS2C_xxx`

示例：

```protobuf
syntax = "proto3";
option java_outer_classname = "TaskProto";
package org.sunrise.game.genProto.gen;

enum FROM_CLIENT {
  C2S_GetTaskList = 0;
  C2S_AcceptTask = 1;
}

enum FROM_SERVER {
  S2C_GetTaskList = 0;
  S2C_TaskUpdate = 1;
}

message MC2S_AcceptTask {
  uint32 taskId = 1;
}
```

## 3.4 空消息规范

如果某个请求不需要参数，例如：

- 获取列表
- 打开界面

可以不定义 `message`，只传 `type + packetId`。

对应 handler 只写：

```java
public static void getTaskList(HumanObject humanObject)
```

---

## 4. 第二步：在 packet.proto 注册 TOPIC

编辑：

```text
gen/src/main/java/org/sunrise/game/genProto/proto/packet.proto
```

加入新的模块类型，例如：

```protobuf
enum TOPIC {
  TOPIC_TYPE_LOGIN = 0;
  TOPIC_TYPE_HUMAN = 1;
  TOPIC_TYPE_TASK = 6;
  TOPIC_TYPE_ACHIEVEMENT = 10;
}
```

注意：

- 数值必须唯一
- 一旦对外发布，尽量不要随意改旧值

---

## 5. 第三步：生成协议代码

执行协议生成脚本：

```bat
gen/src/main/java/org/sunrise/game/genProto/gen.bat
```

生成后会得到：

```text
gen/src/main/java/org/sunrise/game/genProto/gen/AchievementProto.java
```

后续 game/client 都直接引用这个生成类。

---

## 6. 第四步：创建玩家模块 Module

## 6.1 放置位置

目录：

```text
game/src/main/java/org/sunrise/game/game/modules/
```

例如：

```text
AchievementModule.java
```

## 6.2 模块职责

`Module` 负责：

- 模块数据内存态
- 初始化新角色默认值
- 从 `role_data` 加载
- 保存到 `role_data`
- 登录时推送给客户端
- 提供业务方法给 handler 调用

## 6.3 需要实现的生命周期

所有模块都继承 `BaseModule`，重点关注：

### `init()`

- 新角色创建时调用
- 初始化默认值
- 不能在这里发协议

### `load()`

- 老角色上线时调用
- 从模块自己的 `dataMap` 中恢复数据

### `save()`

- 定时存库或下线时调用
- 把内存数据写回 `dataMap`

### `sendToClient()`

- 登录后统一调用
- 把该模块数据同步给客户端

## 6.4 数据存储方式

每个模块都通过：

- `putDbData(key, value)`
- `getDbData(key, typeReference, callback)`

把自身数据存到：

- `human_info.role_data`

最终是：

```text
模块名 -> JSON 字符串
```

所以新增字段时要注意：

- 老号可能没有该字段
- `load()` 中要处理空值与默认值

## 6.5 模块示例骨架

```java
@Getter
@Setter
public class AchievementModule extends BaseModule {
    private Map<Integer, Integer> progress = new HashMap<>();

    public AchievementModule(String humanId) {
        super(humanId);
    }

    @Override
    public void init() {
        progress = new HashMap<>();
    }

    @Override
    public void load() {
        getDbData("progress", new TypeReference<Map<Integer, Integer>>() {}, value -> {
            if (value != null) {
                progress = value;
            }
        });
    }

    @Override
    public void save() {
        putDbData("progress", progress);
    }

    @Override
    public void sendToClient() {
        sendAll();
    }

    public void sendAll() {
        // 构建并发送协议
    }
}
```

---

## 7. 第五步：注册到 HumanObject

新增模块后，必须在：

```java
HumanObject.createModules()
```

中注册，否则：

- 不会创建实例
- 不会执行生命周期
- `getModule()` 取不到

示例：

```java
modules.put(AchievementModule.class.getSimpleName(), new AchievementModule(humanId));
```

这是新增玩家模块最容易漏的一步。

---

## 8. 第六步：创建消息处理器 MsgHandler

## 8.1 放置位置

建议放在：

```text
game/src/main/java/org/sunrise/game/game/logic/<业务目录>/
```

例如：

```text
game/logic/achievement/AchievementMsgHandler.java
```

## 8.2 类与方法注解

类上加：

```java
@MsgHandlerClass(packetType = TopicProto.TOPIC.TOPIC_TYPE_ACHIEVEMENT_VALUE)
```

方法上加：

```java
@MsgHandlerMethod(packetId = AchievementProto.FROM_CLIENT.C2S_Claim_VALUE)
```

## 8.3 方法签名规则

必须是 `static` 方法，参数只支持两种形态：

### 空消息

```java
public static void getList(HumanObject humanObject)
```

### 带协议体

```java
public static void claim(HumanObject humanObject, AchievementProto.MC2S_Claim data)
```

第一个参数必须是：

- `HumanObject`

## 8.4 示例

```java
@MsgHandlerClass(packetType = TopicProto.TOPIC.TOPIC_TYPE_ACHIEVEMENT_VALUE)
public class AchievementMsgHandler {

    @MsgHandlerMethod(packetId = AchievementProto.FROM_CLIENT.C2S_GetList_VALUE)
    public static void getList(HumanObject humanObject) {
        humanObject.getModule(AchievementModule.class).sendAll();
    }

    @MsgHandlerMethod(packetId = AchievementProto.FROM_CLIENT.C2S_Claim_VALUE)
    public static void claim(HumanObject humanObject, AchievementProto.MC2S_Claim data) {
        humanObject.getModule(AchievementModule.class).claim(data.getId());
    }
}
```

## 8.5 为什么不需要手动注册

因为游戏服启动时会执行：

- `ProtoParserUtils.init()`
- `LogicUtils.init(Collections.singletonList("org.sunrise.game.game.logic"))`

框架会自动：

- 扫描所有 handler 类
- 建立 `packetType + packetId -> method` 映射
- 自动找到对应 protobuf 的 `parseFrom()`

---

## 9. 第七步：如果涉及跨服，新增 global RPC 服务

如果业务需要跨玩家共享状态，不能只放在单个 game 服内存中。

典型判断标准：

- 需要跨逻辑服访问
- 需要全服广播
- 需要所有玩家共享同一份数据

这类功能应该放到 `global/`。

## 9.1 新增 global 服务类

目录示例：

```text
game/src/main/java/org/sunrise/game/global/service/achievement/
```

定义：

```java
@RpcService
public class AchievementService extends BaseService {

    public AchievementService(String nodeId) {
        super(nodeId);
    }

    @RpcMethod
    public void claimReward(String humanId, int achievementId) {
        // 处理跨服共享逻辑
        returns("success", true);
    }
}
```

## 9.2 在 game 服中通过 RpcFunction 调用

```java
RpcFunction rpcFunction = RpcFunction.newInstance();
rpcFunction.call(CallEnum.AchievementService_claimReward,
        "humanId", getHumanId(),
        "achievementId", id);
rpcFunction.listenResult(rpcResult -> {
    Boolean success = (Boolean) rpcResult.getData("success");
});
```

## 9.3 注意 RPC 的顺序约束

调用参数必须与方法参数顺序一一对应，例如：

```java
public void claimReward(String humanId, int achievementId)
```

则 `call()` 里必须按：

```java
"humanId", value1,
"achievementId", value2
```

的顺序传，不能交换。

---

## 10. 第八步：如果需要异步回推，新增 game 监听服务

如果 global 服处理完后，需要主动通知某个玩家所在 game 节点，则新增一个 game 侧 `RpcListenService`。

现有例子：

- `ChatRpcListenService`
- `FriendRpcListenService`
- `MailRpcListenService`

## 10.1 示例

```java
@RpcService
public class AchievementRpcListenService extends BaseService {
    public AchievementRpcListenService(String nodeId) {
        super(nodeId);
    }

    @RpcMethod
    public void onAchievementUpdate(String humanId, byte[] protoData) {
        HumanObject human = HumanObjectManger.getHumanObject(humanId);
        if (human != null) {
            human.sendMsg(TopicProto.TOPIC.TOPIC_TYPE_ACHIEVEMENT_VALUE,
                    AchievementProto.FROM_SERVER.S2C_Update_VALUE,
                    protoData);
        }
    }
}
```

## 10.2 广播还是定向

- 如果目标玩家可能在任意 game 节点：通常用 `SendAll`
- 如果你已经明确知道目标节点：用 `SendDesignated`

---

## 11. 第九步：如果需要配置表，补充 tables 与 Config 读取

## 11.1 什么时候要配表

以下场景建议用配置表：

- 奖励参数
- 数值策划配置
- 活动时间
- 道具定义
- 条件门槛

## 11.2 配置表流程

1. 在 `tables/Datas/` 新增或修改 Excel
2. 运行 `tables/gen.bat`
3. 生成 JSON 到 `tables/json/`
4. 生成 Java 配置类到 `game/.../config/`
5. 游戏服启动时 `ConfigUtils.load()` 自动加载

## 11.3 运行时读取

通过 `Tables` 静态对象访问，例如：

```java
Tables.ConfigTask.get(taskId)
Tables.ConfigItem.get(itemId)
Tables.ConfigParam.getItemBoxCapacity()
```

## 11.4 热更配置

GM 后台“配置更新”本质上会广播：

- `reloadConfig`

game 服收到后执行：

- `ConfigUtils.load()`

所以新增功能如果走 `Tables`，天然支持热更配置重载。

---

## 12. 第十步：如果需要周期逻辑，考虑接入系统层

如果功能不是简单的“收到请求时才运行”，而是：

- 每秒 / 每分钟刷新
- 跨天重置
- 活动状态切换
- 全服定时任务

则应放到系统层。

## 12.1 新增 BaseSystem 子类

例如：

```java
public class AchievementSystem extends BaseSystem {
    @Override
    public void init() {}

    @Override
    public void load() {}

    @Override
    public void pulse() {}
}
```

## 12.2 注册到 GameSystem

在 `GameSystem.createSystems()` 中加入：

```java
systems.put(AchievementSystem.class.getSimpleName(), new AchievementSystem());
```

## 12.3 玩家模块访问系统

```java
AchievementSystem system = GameSystem.getSystem(AchievementSystem.class);
```

这样适合承载：

- 全局状态
- 周期心跳逻辑
- 共享配置运行时状态

---

## 13. 第十一步：客户端适配

如果只是服务端功能联调，可先用 `sunrise-client` 手工发包。

如果要给发送工具适配新协议：

- 只要 `.proto` 已生成
- `MessageUtil.init()` 会按命名规则自动注册 topic / packet / parser

这也是本项目做协议调试非常方便的一点。

机器人如果需要主动测试该功能，则在：

- `MessageHandler`
- `BotManager`

里补对应逻辑。

---

## 14. 第十二步：测试与验证清单

新增完模块后，建议最少做以下验证：

### 14.1 编译验证

```bash
mvn clean package
```

确认：

- proto 正常生成
- game 模块能编译通过
- 打包成功

### 14.2 登录验证

- 新角色创建时 `init()` 是否生效
- 老角色登录时 `load()` 是否正确
- 登录后 `sendToClient()` 是否发包

### 14.3 存档验证

- 在线修改数据后，检查定时存库是否生效
- 下线重登后数据是否恢复
- 新增字段在老号上是否有默认值

### 14.4 协议验证

- 空消息是否能正确路由
- 带 body 的消息是否能正确 parse
- `packetType` / `packetId` 是否对应正确

### 14.5 RPC 验证（如有）

- `CallEnum` 是否包含新方法
- `CallUtils.init()` 是否注册到
- 回调是否能收到正确字段
- 广播 / 定向调用是否符合预期

### 14.6 GM / 热更验证（如有配置）

- 配表改动是否可重载
- `reloadConfig` 后是否立即生效

---

## 15. 新增功能时最常见的坑

## 15.1 忘记在 `packet.proto` 注册 TOPIC

表现：

- 解析器注册不到
- 客户端或服务端收不到对应协议

## 15.2 proto 命名不符合规则

表现：

- `ProtoParserUtils` 或 `MessageUtil` 反射失败
- 自动注册失败

典型错误：

- `TOPIC_TYPE_ACHIEVE`，但类名写成 `AchievementProto`
- `C2S_DoThing`，message 却写成 `MDoThing`

## 15.3 忘记在 `HumanObject.createModules()` 注册模块

表现：

- `getModule()` 返回 null
- `init/load/save/sendToClient` 都不执行

## 15.4 `sendToClient()` 漏发登录同步数据

表现：

- 服务端有数据，客户端登录后界面空白

## 15.5 `save()` 漏写字段

表现：

- 在线逻辑正常
- 重新登录后数据丢失

## 15.6 `load()` 没处理老数据兼容

表现：

- 老号升级后空指针
- 新增字段默认值异常

## 15.7 RPC 参数顺序写错

表现：

- 方法能调到，但数据乱位
- 返回结果异常，且不容易第一时间看出来

## 15.8 需要跨服却把数据只放在 game 本地

表现：

- A 服能看到，B 服看不到
- 切换逻辑节点后数据不一致

---

## 16. 推荐的新增功能模板

如果你要新增一个标准玩家功能，推荐直接套下面模板：

1. 新建 `xxx.proto`
2. 在 `packet.proto` 注册 `TOPIC_TYPE_XXX`
3. 生成 proto
4. 新建 `XxxModule`
5. 在 `HumanObject` 注册模块
6. 新建 `XxxMsgHandler`
7. 如果涉及共享状态，再新建 `global/service/XxxService`
8. 如果需要主动推送，再新建 `game/service/XxxRpcListenService`
9. 如果需要数值配置，再加 `tables` 配置
10. 编译、启动、用 `sunrise-client` 联调

---

## 17. 总结

本项目新增 game 功能的核心思路是：

- 协议先行
- 路由自动注册
- 玩家数据模块化存档
- 跨服能力下沉到 global
- 定时逻辑交给 system
- 外部运维能力走 gmback

只要遵守以下 4 条，一般就不会偏：

1. `proto / TOPIC / 类名` 命名严格一致
2. 玩家私有数据放 `Module`
3. 跨服共享数据放 `GlobalService`
4. 所有新增模块都必须完成 `init/load/save/sendToClient` 四件事
